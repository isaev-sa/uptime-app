# Документация маршрутов API

Применяй этот навык в рамках задачи, когда добавляется, меняется или удаляется маршрут backend API или его контракт запроса либо ответа. Перед изменениями прочитай `backend/AGENTS.md` и соблюдай актуальные правила документации проекта.

1. Сверь регистрацию затронутых маршрутов с обработчиками и фактическим поведением: методом, путём, параметрами, телом запроса, авторизацией, типами и кодами ответов. Учитывай middleware и общие типы, если они влияют на контракт.
2. Добавь или обнови swaggo-аннотации для каждого затронутого маршрута; для удалённого маршрута удали устаревшие аннотации. Если один обработчик обслуживает несколько методов, следуй существующему в проекте подходу с отдельными аннотированными обёртками. Схемы должны соответствовать реальным данным, а не предполагаемому поведению.
3. После синхронизации аннотаций запусти из корня проекта `.codex/skills/openapi-routes/scripts/generate.sh`: скрипт генерирует OpenAPI и затем ReDoc. Включи полученные `backend/docs/swagger.json`, `backend/docs/swagger.yaml` и `backend/docs/redoc.html` в изменения. Если правила генерации в `backend/AGENTS.md` изменились, приведи скрипт в соответствие с ними.
4. Проверь, что сгенерированные операции и схемы соответствуют маршрутам и контрактам, включая отсутствие удалённых операций; выполни проверки, подходящие к изменению. Если генерация или проверка невозможна, сообщи об этом и укажи причину.
