# Регистрация и авторизация пользователей

## Результат

Реализовать на Go API регистрации и входа по email и паролю с выдачей JWT access-токена и refresh-токена. Пользователи и сессии хранятся в PostgreSQL. Для локального запуска добавить Docker Compose.

## Реализация

- Добавить HTTP-сервер и API:
  - `POST /auth/register` — регистрация по email и паролю, создание сессии и выдача токенов.
  - `POST /auth/login` — проверка учётных данных и выдача токенов.
  - `POST /auth/refresh` — проверка refresh-токена и выдача новой пары токенов.
- Возвращать access-токен в JSON; refresh-токен устанавливать в `HttpOnly` cookie. Настроить `SameSite`, `Secure` и разрешённый origin через конфигурацию для локальной разработки и развёртывания по HTTPS.
- Использовать **GORM** и его драйвер PostgreSQL для моделей и запросов. Создать версионированные SQL-миграции для таблиц, ограничений и индексов; не полагаться на `AutoMigrate` при запуске приложения.
- Хранить пароли только в виде стойких хешей. Email нормализовать и обеспечить его уникальность на уровне базы данных. Возвращать понятные HTTP-ошибки без раскрытия того, существует ли пользователь при неудачном входе.
- Хранить в базе хеши refresh-токенов и сроки их действия. При каждом обновлении атомарно заменять refresh-токен в транзакции; повторное использование старого токена отклонять.
- Подписывать JWT секретом из конфигурации, включать идентификатор пользователя и срок действия. Добавить проверку конфигурации при запуске.
- Добавить Docker Compose для запуска PostgreSQL и бэкенда, постоянный том для данных и документацию по настройке, запуску, миграциям и вызовам API.

## Принятые решения

- Регистрация сразу авторизует пользователя. Восстановление пароля и интерфейс фронтенда в эту задачу не входят.
- Срок действия access-токена по умолчанию — 15 минут, refresh-токена — 30 дней; оба срока настраиваются.
- Для локальной разработки разрешён origin `http://localhost:3000`; production-origin и секреты задаются через окружение.
